# 非機能要件

## 性能

- APIレスポンスは5秒以内とする
- 5秒を超過した場合、再試行可能なAPIについては規定回数まで再試行する
- 再試行によっても成功しない場合、または再試行不可な処理についてはタイムアウトエラーとする
- タイムアウトエラー発生時は、ユーザーが再実行可能な状態とする
- 同時アクセス数10ユーザーを処理できること

## 可用性

- v0.1.0では高可用性を目的とした追加構成は行わない
- サービス停止時間は月10時間以内を目標とする
- 個別のスケーリング設定は行わない
- 障害発生時の復旧対応はベストエフォートとする

## セキュリティ

- 公開ページおよび認証に必要な処理を除き、原則として認証を必須とする
- ユーザーは自身に紐づく情報のみ参照・操作できること
- Secretは原則としてAWS Secrets Manager等の適切なSecret管理サービスで管理する
- AWSリソースに付与する権限は最小権限とする
- 通信はHTTPSを利用する

## データ保護

- 退会したユーザーデータは論理削除とする
- 永続化データのバックアップを定期的に取得する
- 復旧時は利用可能なバックアップまたは復旧ポイントから復元する
- v0.1.0では一定量のデータ損失を許容する

## ログ

- APIアクセスログをCloudWatchへ保存する
- アプリケーションログをCloudWatchへ保存する
- 認証関連で取得可能なログを保存する
- ログの保存期間は30日とする
- 個人情報およびSecretをログへ出力しない

## 監視

- v0.1.0では独自の監視基盤を構築しない
- AWSマネージドサービスから確認可能なメトリクスおよびログを利用して障害調査を行う

## 運用性

- リリース時にバージョンタグを付与する
- 緊急時に以前のリリースバージョンへロールバックできること
- インフラストラクチャは原則としてIaCで管理する
- デプロイは原則としてCI/CD Workflow経由で実施する
- 通常運用ではAWSリソースへの手動変更を行わない

## デプロイ

- GitHub Actionsを利用してCI/CDを実行する
- デプロイ失敗時は原則として修正後に再デプロイする
- 緊急対応が必要な場合は直前の安定バージョンへロールバックする

## テスト

- 単体テストを実装する
- 結合テストを実装する
- E2Eテストを実装する
- テストはCI上で自動実行する

## 保守性

- PythonコードはRuffを利用してLintおよびFormatを実施する
- PythonコードはPyrightを利用してType Checkを実施する
- Pythonの依存ライブラリはuvで管理する
- 依存ライブラリはlockファイルによってバージョンを固定する
- 利用中の依存ライブラリに対応が必要な脆弱性が確認された場合は、更新および動作確認を行った上でデプロイする

## コスト

- 常時稼働するリソースを可能な限り利用しない
- AWS予算アラートを設定する
- AWS利用料金は月額10,000円以内を目標とする

## 互換性

- Google Chromeの最新安定版をサポート対象とする
- その他のブラウザについてはv0.1.0では動作保証の対象外とする

## ユーザビリティ

- ユーザーが主要機能をWeb UIから操作できること
- エラー発生時はユーザーが次の操作を判断できる情報を表示する

## アクセシビリティ

- v0.1.0では明示的なアクセシビリティ基準への準拠を要件としない

## 可観測性

- AWSマネージドサービスが提供するログおよびメトリクスを利用して、障害発生時に原因調査できること

## 災害対策・復旧

- v0.1.0ではRTOを定義しない
- 復旧対応はベストエフォートとする

## コンプライアンス・プライバシー

- 退会後の復旧を可能とするため、退会時も必要なユーザーデータを保持する
- 外部IdPから取得するユーザー属性は必要最小限とする

## 制約

- AWSを利用する
- AWS利用料金は月額10,000円以内とする
- 日本国内での利用を主な対象とする
- 開発・運用は1名で行う
