# ADR-0005: バックエンドに AWS Lambda を採用する

## ステータス

承認

## コンテキスト

47log では、訪問状況の取得・登録・更新などを処理するバックエンドが必要である。
初期リリース時点ではアクセス頻度が低いと想定しており、常時稼働するコンピュートリソースを必要としない構成にしたい。

## 決定

バックエンドの処理基盤には AWS Lambda を採用し、Amazon API Gateway から呼び出す。

## 理由

- Lambda は実行時間に応じた従量課金であり、常時稼働するコンピュートリソースを必要としない。ECS/Fargate などの常時稼働構成と比較して、初期段階のコストを抑えやすい。
- API Gateway と直接統合でき、HTTP API のルーティング先として Lambda 関数を設定できる。
- API Gateway と Cognito を組み合わせて認証・認可を入口に集約できるため、Lambda は業務処理に専念でき、サーバーレス構成としてシンプルに実装できる。

## 影響

- API Gateway のルートと Lambda 関数を対応付ける必要がある。
- Lambda には DynamoDB など必要な AWS リソースだけにアクセスできる最小権限の IAM ロールを設定する。
- 初回アクセス時のコールドスタートと、実行時間・メモリなどの Lambda 制約を考慮して実装する。
