# ADR-0004: フロントエンドを CloudFront + S3 の SPA 構成にする

## ステータス

承認

## コンテキスト

47log のフロントエンドは、初期リリースでは動的なサーバーサイドレンダリングを必要としない。
クライアントサイドで動作する SPA として提供すれば要件を満たせる。

## 決定

フロントエンドは SPA としてビルドし、静的ファイルを Amazon S3 に配置して Amazon CloudFront から配信する。
ビルドは AWS Amplify Hosting ではなく GitHub Actions で実行する。

## 理由

- 現時点の要件は SPA 構成で十分であり、SSR などのサーバーサイド実行環境を必要としない。
- Amplify Hosting のビルド・ホスティング機能を利用せず、GitHub Actions でビルドすることで、必要な S3 と CloudFront に構成を絞れる。初期段階では Amplify 構成と比較してコストを抑えやすい。
- S3 は静的ファイルの保存先、CloudFront は CDN と HTTPS 配信の入口として役割が明確であり、静的 SPA の配信に適している。

## 影響

- GitHub Actions でフロントエンドをビルドし、生成物を S3 へデプロイするワークフローを構築する必要がある。
- S3 バケットは非公開とし、CloudFront Origin Access Control (OAC) 経由でのみコンテンツを読み取れるようにする。
- SPA のクライアントサイドルーティングに対応するため、存在しないパスへのアクセス時は `index.html` を返すよう CloudFront を設定する。
- 実際の費用は配信量・リクエスト数に依存するため、運用開始後に利用状況を確認する。
