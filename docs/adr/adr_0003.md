# ADR-0003: API の入口に Amazon API Gateway を採用する

## ステータス

承認

## コンテキスト

47log では、クライアントからバックエンドの機能を呼び出すための HTTP API が必要である。
常駐型コンテナサービスである ECS などは、リクエストの有無にかかわらずコンテナを稼働させる構成では料金が発生する。

## 決定

HTTP API の入口には Amazon API Gateway を採用する。
バックエンドは、可能な限り Lambda などのサーバーレス統合を利用する。

## 理由

- API Gateway は AWS のフルマネージドサービスであり、リクエストに応じて利用する構成にできるため、常駐コンテナを維持する構成と比べて初期段階の固定費を抑えやすい。
- 認証・認可を API の入口に一元化できる。Cognito と連携して、保護された API へのアクセスを制御できる。
- パスや HTTP メソッドに応じてバックエンドへルーティングできるため、クライアントとバックエンドを疎結合にできる。

## 影響

- API Gateway は API の入口であり、処理を実行するバックエンド自体は別途必要である。
- コンテナをバックエンドとして常駐させる場合は、そのコンテナ料金は引き続き発生する。
- API のルーティング、CORS、認可設定、およびバックエンド統合を API Gateway に定義する必要がある。
